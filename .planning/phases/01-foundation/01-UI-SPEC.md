## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline gaps (sidebar icon-to-label) |
| sm | 8px | Compact element spacing, topbar padding, table cell padding |
| md | 16px | Default element spacing, card padding, content area padding |
| lg | 24px | Section padding, form group spacing |
| xl | 32px | Layout gaps, between major content sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level vertical rhythm |

Exceptions:
- Touch/click targets on interactive sidebar items: minimum 44px height (accessibility floor, even though desktop-only)
- Sidebar width: 240px fixed (derived from v1 reference sidebar proportions)
- Topbar height: 48px fixed
- Modal max-width: 680px standard, 960px for wide modals (matches v1 `.modal` and `.modal.xl`)

**Source:** v1 reference CSS (`.topbar` 8px/16px padding, `.card` 16px, `.content` 18px), CONTEXT.md D-10 (1024px minimum viewport).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5 | Table cells, form values, modal body text, list items |
| Label | 11px | 500 (medium) | 1.4 | Table headers (uppercase + letter-spacing 0.06em), form field labels (uppercase + letter-spacing 0.05em), stat card labels |
| Heading | 15px | 600 (semibold) | 1.3 | Card headers, section titles, sidebar section group labels |
| Display | 22px | 700 (bold) | 1.2 | Stat card values (large numbers), login panel title |

**Typography rules:**
- Table headers use `text-transform: uppercase` and `letter-spacing: 0.06em` at 11px/weight-500 — this is the v1 pattern and must be preserved.
- Form field labels use `text-transform: uppercase` and `letter-spacing: 0.05em` at 11px — same pattern.
- Section divider labels (e.g. "STAFF ACCOUNTS", "MEMBER ACCOUNTS") use gold color at 12px/weight-600/uppercase — these are the v1 `.sh h3` pattern.
- Brand/logo text in the topbar: 15px/weight-700, gold color, `letter-spacing: 0.05em`.
- No font downloads. System stack resolves to Segoe UI on Windows (primary user machines), system-ui fallback elsewhere.

**Source:** v1 reference CSS (`font-size: 14px` body, `th` 10px uppercase, `.card-hdr h2` 15px/600, `.scard .sv` 22px/700), D-17.

## Color

All values are authoritative from D-16 and must be defined as CSS custom properties in `src/app.css`. Never hardcode hex values in component files.

| Role | Value | Usage |
|------|-------|-------|
| Background primary (60%) | `#1a1410` | Page background, root `<body>`, main content area |
| Background secondary (30%) | `#231d14` | Cards, sidebar, topbar, modal backgrounds, nav |
| Background tertiary | `#2c2518` | Input fields, hover states, secondary card backgrounds, stat cards |
| Gold accent (10%) | `#c4a45a` | See reserved list below |
| Gold hover | `#d4b46a` | Gold accent elements on `:hover` state |
| Text primary | `#d4c5a0` | All body text, table cells, heading text, form values |
| Text muted | `#8b7d65` | Secondary text, table headers, labels, timestamps, placeholder text |
| Border | `#3d3426` | All borders — cards, sidebar, table rows, inputs, dividers |
| Danger | `#8b2b2b` | Destructive actions only (see below) |
| Success | `#3d6b3d` | Positive state only (active/enabled badges) |

**Accent (`#c4a45a`) is reserved for:**
1. Active sidebar navigation item (text color + left border indicator)
2. Focused input field border (`border-color` on `:focus`)
3. Primary CTA button (gold-outlined variant — NOT filled gold background)
4. Section divider labels (e.g. "STAFF ACCOUNTS" group headings)
5. Stat card value numbers when representing positive/notable data
6. Brand/logo text in topbar
7. Active tab underline in tabbed sub-navigation (modals only)
8. `ring` color for shadcn focus rings

**Danger (`#8b2b2b`) is reserved for:**
- Destructive action buttons (deactivate account, delete)
- Danger alert/notice backgrounds (with `rgba(139,43,43,0.12)` fill, `rgba(139,43,43,0.30)` border)
- Error state copy

**Success (`#3d6b3d`) is reserved for:**
- Active/enabled state badges
- Success alert backgrounds (with `rgba(61,107,61,0.12)` fill)

**Always dark mode.** No light mode. No theme toggle. The app is locked to dark mode — no `prefers-color-scheme` handling needed (D-15).

**Source:** D-15, D-16, RESEARCH.md Pattern 5, v1 reference CSS (`:root` custom properties).

## Interaction Contracts

### Form Interactions (UX-02)

- All forms use SvelteKit `use:enhance` for progressive enhancement (no full page reload)
- Validation errors appear inline below each field, not in a top-level banner (unless it is a global error)
- Required field indicators: asterisk (*) next to field label, danger color
- Submit buttons disable during pending request and show a spinner (Lucide `Loader2` with `animate-spin`)
- After successful form submission: modal closes, table refreshes, success toast or inline confirmation appears
- After failed form submission: error shown inline, form re-enables, focus moves to first error field

### Navigation Interactions

- Clicking a disabled nav item: no navigation, tooltip appears on hover explaining "Coming in Phase N"
- Active route: highlighted in sidebar immediately (SvelteKit `$page.url.pathname` comparison)
- Clicking "Sign Out": posts to logout action, clears PocketBase auth cookie, redirects to `/login` with no error message

### Destructive Action Pattern

Every destructive action (deactivate account) requires a confirmation dialog — never a `window.confirm()`. Dialog follows the modal pattern defined above. The confirmation button text must repeat the action name: "Deactivate Account" (not "Confirm" or "Yes").

### Role-Gated Element Pattern

- Elements the current user cannot act on are not rendered at all (server-side conditional rendering)
- Do not render action buttons then disable them for unauthorized users — omit them entirely
- The read-only notice bar (info alert) communicates the permission boundary for the entire page
- This satisfies the principle that role enforcement is visible and tested (CONTEXT.md specifics)

### Error Recovery

- Network error during form submit: alert danger banner "Something went wrong. Please try again." — the form data is preserved so the user does not re-enter everything
- PocketBase returns 403 (unauthorized): alert danger "You don't have permission to perform this action." — this should only surface if there is a bug in role gating
- PocketBase returns 400 (validation error): map field-level error messages from PocketBase response to inline field errors
