## Decisions Made

- **job_run_log exists() guard**: The collection was already created in the Phase 2 migration (P1-4). The Phase 3 migration includes an `exists()` guard so it is skipped on production installs where Phase 2 has run. The guard only fires on fresh installs. `job_run_log` is included in the Phase 3 revert to handle that fresh-install case.
- **last_processed_ts as text**: Per RESEARCH.md Open Question 2 resolution, this is stored as a text field holding an ISO string rather than a date field, to match the idempotency check pattern in the scheduler: `cfg.getString("last_processed_ts") === deadlineTs`.
- **svelte5-chartjs not svelte-chartjs**: The Svelte 4 wrapper (`svelte-chartjs`) was explicitly not installed. `svelte5-chartjs@1.0.0` is the purpose-built Svelte 5 native replacement (RESEARCH.md Pitfall 7).

## Deviations from Plan

None - plan executed exactly as written.

The `job_run_log` collection existence from Phase 2 was noted in RESEARCH.md Open Questions and handled by the `exists()` guard as designed. Not a deviation.

File existence was verified directly (`node_modules/svelte5-chartjs/package.json` exists, version 1.0.0). The package will import correctly in the Vite/SvelteKit ESM build environment.
