## Spacing Scale

**Unchanged from Phases 1 & 2.** Reference 01-UI-SPEC.md. Reproduced here for executor convenience:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline gaps |
| sm | 8px | Compact element spacing, table cell padding |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, form group spacing, modal padding |
| xl | 32px | Layout gaps, between major content sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level vertical rhythm |

- Cap preview progress bar: 8px height (`h-2`), full width of form column

### New: Submission Form (Modal)

Used both on node detail page and in quick-log modal from dashboard.
Modal width: 560px.

```
Modal title: "Log Submission" (for upkeep type, pre-selected)
             "Log Repair" (for repair type)
             "Log Upgrade" (for upgrade type)
             "Reduce Instability" (for instability_reduction type)

Fields (top to bottom):
  [Submission Type — Select, full width]
    Options: Upkeep / Repair / Upgrade / Reduce Instability

  [--- for "Upkeep" type ---]
    Item (Select from sp_catalogue, searchable, required)
    Quantity (number input, min 1, required)

              in 14px/400/text-muted + 14px/600/gold for the total

  [--- for "Repair" type ---]
    Item field replaced by read-only display: "Repair — [node tier label]"

  [--- for "Upgrade" type ---]

  (see "Cap Preview Component" below)

  Submit button NOT blocked for repair/upgrade/instability_reduction (these are special types,
  not subject to category caps — see CLAUDE.md checkCaps()).
```

### New: Cap Preview Component

Embedded inside the Submission Form modal. Always visible, updates live before any submit.

```
CAP PREVIEW [label — 11px/600/gold/uppercase, mb-8px]
[Two rows — one per capped category]

Row: "Raw Renewable"
  [progress bar — full width, h-2, bg-muted track]
    fill color: safe (#3d6b3d) / warning (#d4c060) / exceeded (#8b2b2b) per thresholds
    current fill: existing rrSP / effective_upkeep (current cycle, before this submission)
    projected fill: (existing rrSP + new sp) / effective_upkeep (after this submission)
    The projected segment is shown as a lighter-opacity extension of the fill
    40% threshold line: absolute-positioned 1px vertical line at 40% of bar width, color #8b7d65
  [Below bar, row]:
    Left: "[N] SP used / [cap_sp] SP cap" (11px/400/text-muted)
    Right (if this submission adds to this category):
      if safe: "→ [new_pct]% after this submission" (11px/400/text-muted)
      if warning: "→ [new_pct]% — approaching 40% cap" (11px/600 #d4c060)
      if exceeded: "→ [new_pct]% — exceeds 40% cap" (11px/600 #ff7070)

Row: "Currency"
  [same structure as Raw Renewable row]

[If upkeep type AND submission would exceed either cap:]
  Inline banner below both bars:
    Background: rgba(139,43,43,0.15), border: rgba(200,68,68,0.3), border-radius: 4px, padding: 8px 12px
    Icon: AlertTriangle (Lucide, 14px, #ff7070)
    Text: "This submission exceeds the 40% cap for [category]. It cannot be saved." (14px/400 #ff7070)
  Submit button becomes disabled.

[If submission type is NOT upkeep (repair/upgrade/instability_reduction):]
  Display muted note below bars:
  "Category caps do not apply to [Repair / Upgrade / Instability Reduction] submissions." (11px/400/text-muted)
  Bars are grayed out (opacity 40%) to signal not applicable.
```

Cap values derive from: `effectiveUpkeep = calcUp(node)` computed at read time.
Cap threshold: `effectiveUpkeep × 0.40` per category.

**Source:** UPKEEP-04. CLAUDE.md checkCaps(), 40% Category Caps.

## Interaction Contracts

### Inherited (all apply unchanged)
All Phase 1 and Phase 2 interaction contracts apply. Key ones:
- `use:enhance` on all forms (no full page reload)
- Submit buttons: disabled + `Loader2` spinner during pending request
- Destructive action always requires a confirmation dialog
- Role-gated elements omitted from DOM server-side
- Inline field validation errors (danger color, 11px/400, below each field)
- Reactive list filters: text search debounced 300ms, selects immediate

### Phase 3 New Interaction Contracts

**Submission form — live SP calculation:**
- SP total updates immediately on every qty keypress (Svelte `$derived`, no debounce)
- Cap preview bars update simultaneously
- Submit button enables/disables without any button click needed

**Submission form — cap enforcement:**
- For `upkeep` type: submit button is disabled (not just warned) when projected usage exceeds 40% cap
- For `repair`, `upgrade`, `instability_reduction` types: submit button is never disabled by cap logic
- Cap preview is always visible regardless of type; bars gray out for non-capped types

**Instability roll — sequence:**
1. "Roll d100" button clicked → button replaced by spinner
2. Random 1–100 value generated client-side via `Math.floor(Math.random() * 100) + 1`
3. Dice display appears with roll value (no animation required — instant render)
4. If triggered: event card appears immediately below dice
5. Staff selects an action button → button disabled + spinner → server action runs
6. On success: `roll_due = false` saved; page `invalidate` causes Instability Roll section to disappear
7. Roll is always saved to `instability_rolls` regardless of triggered/not-triggered

**Instability roll — dismiss without resolving:**
- "Resolve / Dismiss" is always available, even for triggered events
- Clicking it shows a confirmation: "Mark this roll as resolved without taking further action? The roll result will still be logged." Confirm: "Resolve" (gold). Cancel: ghost.

**Deadline config form:**
- "Next deadline" preview computes in real time as day/hour/minute/offset inputs change (`$derived`)
- Save uses `use:enhance` with success toast: "Deadline configuration saved." (14px/400, bg-card, border-border, 3 second auto-dismiss — same toast pattern as Phase 1)
- No confirmation required for saves (it is not destructive)

**Metrics page — chart and table sync:**
- Faction filter in "Weekly Chart" tab is independent from faction filter in "SP Totals" tab
- Group By and date range filters are local to the SP Totals tab
- No URL query parameters for metrics filters (short admin sessions, same as Phase 2)

**Remove submission:**
- Confirmation dialog (shadcn Dialog) required before removal, per inherited destructive contract
- After removal: SvelteKit `invalidate` updates cycle totals and cap preview on the node detail page

**Bulk process (UPKEEP-10):**
- "Process All Overdue" action on dashboard (if implemented as a button): requires confirmation dialog
  Title: "Process All Overdue Nodes"
  Body: "This will run deadline processing for all nodes that have passed their deadline. Nodes already processed this cycle will be skipped automatically."
  Confirm: "Process All" (gold variant — NOT danger, this is the normal workflow action)
  Cancel: ghost

**Source:** UPKEEP-03, UPKEEP-04, UPKEEP-10, INSTAB-02, INSTAB-04, INSTAB-06. CLAUDE.md idempotency constraint.
